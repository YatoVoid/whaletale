Reference

WhaleTale operations handbook

WhaleTale turns a property's existing security cameras into per-space foot-traffic data, so the operator of a multi-tenant space (a market, a food hall, an antique mall, mixed-use retail) can price it, fill it, and prove its value to tenants.

Video never leaves the property. An on-prem edge box decodes the camera streams, runs person detection, applies zone logic, and writes counts to a local database. Only kilobyte aggregates sync to the cloud. No frames, crops, embeddings, or movement paths are ever stored or transmitted.

This handbook covers a single-site install: one edge box on the property, a cloud instance, and the operator console, connected over a private Tailscale network with no public ingress. It documents how to run each part, how to use every screen, what each statistic means, and exactly what the system does in the failure scenarios that decide whether an operator still trusts it in month six.

About the interface renderings. The console is a Next.js app you run locally against your cloud API. It is not hosted. The screens below are faithful renderings built from the product's own design system (see DESIGN.md) and the current build, using the demo site's data. They show layout and content, not live pixels.

3 Running it

Prerequisites. uv (pins and fetches Python 3.12), pnpm and Node for the console, Docker for a local Postgres, and the camera onboarding tools if you use ONVIF discovery. PDF rendering needs libpango-1.0-0 libpangoft2-1.0-0 on the cloud host.

Edge box

Onboard each camera first. The gate checks the stream opens, its resolution and decode FPS, and a timed test inference, then prints a site.json block with the RTSP credentials sealed (key derived from WHALETALE_SITE_SECRET).

# discover cameras on the LAN, or validate and emit a config block
uv run whaletale-onboard --discover
uv run whaletale-onboard --source rtsp://u:p@cam/stream1 --name front-hall --emit

Assemble site.json from those blocks. It is never committed, because it carries the pairing token and the sealed credentials. Each zone carries its cloud zone_version_id; a zone with "excluded": true is a staff-only mask, not a counting zone. Then run the agent and the sync client, usually two systemd units from edge/deploy/.

uv run whaletale-agent --config site.json                 # the capture and count daemon
uv run whaletale-agent --config site.json --warm          # load the model, exit (first-run cache)
uv run whaletale-agent --config site.json --recalibrate   # re-capture drift references after moving a camera
uv run whaletale-sync   --config site.json --once          # push the buffered backlog once
uv run whaletale-sync   --config site.json --interval 60   # loop: push and heartbeat every 60s
uv run whaletale-sync   --config site.json --dry-run       # print the pending payload, send nothing
The agent and the sync client must share EDGE_SQLITE_PATH. The agent writes rollups and per-camera health there; the sync client reads them into the heartbeat. Point them at different files and the fleet view goes blank.

Cloud

docker compose -f docker/compose.cloud.yml up -d      # Postgres and Redis
cd cloud && uv sync
uv run alembic upgrade head                             # apply migrations
DATABASE_URL=postgresql+psycopg://… uv run whaletale-api --port 8000
uv run whaletale-report --seed --out report              # one-pager: report.html and report.pdf

The one FastAPI app serves four route groups: /v1/ingest and /v1/heartbeat for edge boxes (pairing-token auth), /v1/* for the operator console (hashed bearer per operator, scoped to their sites), /admin/* for fleet staff (single WHALETALE_ADMIN_TOKEN), and /webhooks/stripe (signature-verified). Every response carries HSTS, nosniff, X-Frame-Options: DENY, and a locked-down CSP. After ten failed auth attempts from one IP in fifteen minutes, that IP is locked out for the window; every auth failure, permission denial, and admin action is one line on the whaletale.security logger.

Console

cd web && pnpm install
cp .env.example .env.local        # set AUTH_SECRET and WHALETALE_API_URL
pnpm dev                          # http://localhost:3000, needs whaletale-api up
pnpm build && pnpm start          # production

Sign in with an operator email and API token. Create the operator on the cloud with create_operator_user(session, email, [site_id]); it returns the raw token once. The console verifies the token by calling GET /v1/sites and carries it on the session. It never reaches the browser bundle.

Bring-up order for one site

  1. Cloud up: Postgres, alembic upgrade head, whaletale-api reachable over Tailscale.
  2. Create the site, its spaces, and a first zone version per space in the database, or via the console once a space exists.
  3. Pair the edge box from the console's Settings screen, and copy the token (shown once) into site.json.
  4. Onboard each camera (whaletale-onboard), add it in Settings, and paste the emitted zone blocks into site.json. Draw an excluded zone over any staff-only area now.
  5. Start whaletale-agent. It captures a drift reference for each camera on its first check.
  6. Start whaletale-sync --interval 60. Rollups and heartbeats begin flowing.
  7. Create the operator user, sign into the console, confirm the Overview health strip shows the box reporting and no cameras offline.
  8. Set up the Stripe subscription for the site if billing is in use; the camera count drives the quantity.

5 Fleet admin

WhaleTale staff, or you helping from a distance. A JSON API, no UI, authed with the single WHALETALE_ADMIN_TOKEN. 6 The statistics

These definitions are canonical (docs/metrics.md, spec §6.4). The console links every label to them. They are computed on the edge per 15-minute bucket and re-derived in the cloud over synced observations, joined to tenancies at query time so a schedule corrected weeks late fixes all history.

MetricDefinitionWhat "good" looks like
EntryA tracked person's ground point (bottom-centre of the box, never the centre) crosses from outside to inside the zone polygon and stays in for at least min_dwell_seconds. Separate enter and exit thresholds keep a boundary loiterer from flickering.Rises on weekends and events; the anomaly flag catches the rest.
Capture rateentries / (entries + passersby). A passerby reaches the zone's catchment but never the polygon.The headline number. High capture in a low-traffic spot is a strong tenant in a weak location, and that is the pricing insight.
Traffic shareZone entries divided by total people at the site for the same bucket.Survives busy days and slow days; use it to compare spaces fairly.
DwellPer-track seconds inside, as median and p90, never a mean (one bag left in frame ruins a mean). The period figure is entries-weighted across buckets, labelled _est.Longer at seating and browsing spaces, short at pass-through.
Occupied secondsWall-clock seconds with at least one person inside. Not a sum over people.Utilisation, distinct from person-seconds (computed on the edge, not synced).
Peak occupancyMax concurrent people inside during the bucket.Capacity planning; catches surges an average hides.

Normalization and flags

Every reported figure carries three comparisons: share of site, against itself (same weekday, trailing four weeks, same hours), and against peer zones of the same kind. Weekday-to-weekday is never the default. A day more than two SD from its trailing baseline is anomalous: surfaced with its annotation (a festival, a closure), never silently excluded. A bucket the primary camera missed and a secondary stood in for is degraded. A bucket a camera produced while running below its own confidence baseline is low-confidence. Both are shown, and both mean "treat as a floor".

7 Edge-case behaviour

The scenarios that decide whether the operator still opens the console in month six. Each row is what actually happens, not an aspiration. Every one has a test (docs/edge-cases.md maps them to the code).

Camera and stream

SituationWhat the system does
A camera drops mid-bucketThe bucket is marked partial and active_cameras is recorded. Counts are never extrapolated to cover the gap.
A camera is bumped or re-aimedAn hourly perceptual hash of the live view diverges from the reference captured at calibration. After two checks past threshold the camera is flagged needs_recalibration, counting for it stops (a visible gap beats wrong numbers), and a camera_moved alert fires. Fix the aim, run whaletale-agent --recalibrate, restart the agent.
The stream stalls without disconnecting (frozen frame)Byte-identical frames for EDGE_FROZEN_FRAME_SECONDS are treated as the camera going offline, exactly like a decode failure.
Camera clock driftsNot a problem here: every frame is stamped with the box's own clock, never the camera's, so a drifted camera clock cannot reach a bucket. Keep the box on NTP.
Resolution or aspect ratio changesZones are stored as normalized coordinates, so they survive it. A flag-for-review signal is not yet emitted.
Night mode or IR switch, or direct sun blowing out the imageThe camera's rolling mean detection confidence is tracked and shipped in the heartbeat. Buckets produced while it sits below the 75th percentile of its own history are marked low-confidence on the report; a sustained drop raises a low_confidence alert. Self-calibrating: an evenly-lit camera never flags.
RTSP credentials rotated by the customer's ITThe decode error surfaces to the operator with the underlying message. Dedicated "auth failed, re-enter credentials" copy is not yet distinct.

Detection and tracking

SituationWhat the system does
A person is occluded then reappears under a new track idA re-entry grace window: a fresh track starting within EDGE_REENTRY_SECONDS and EDGE_REENTRY_DISTANCE of a just-dropped track inherits its visit instead of counting a second entry.
Someone loiters right on the zone boundaryThe dwell threshold plus separate enter and exit thresholds (hysteresis) stop it flickering entries.
Staff walk through the same zone all dayDraw an excluded zone over the staff corridor or behind the counter. Any detection with its feet inside is dropped before any counting zone sees it, so staff crossings never become entries or dwell.
A family of four walks in togetherCounts as four. There is no group de-duplication and there should not be.
The site is empty overnightThe edge emits a bucket only when a zone had activity, so there are no zero-filled 3am rows to misread. Explicit per-site operating hours are not stored yet.

Zones, tenancy and time

SituationWhat the system does
A zone drawn with fewer than 3 points, self-intersecting, or outside the frameRefused at save, in the editor and again server-side (Shapely).
Two zones overlap on one cameraAllowed (a table inside a patio), but the save returns a conflict listing the overlapping spaces until you set a parent/child relation or explicitly acknowledge the overlap.
A space has no tenant for a stretchReported as vacant: a hatched state, real information, distinct from missing data.
Overlapping tenancies on one spaceRejected on save; the conflict is shown, naming both tenancies and the overlapping range.
A tenancy is edited weeks after the factAllowed. Attribution joins tenancies at query time, so every affected past report recomputes.
A recurring tenancy lands on a day the venue was closedCross-referenced against the day annotations and suppressed for that date.
An occupant is renamed or mergedOccupant records are referenced, never copied, so the rename propagates through all history.
A recurring Saturday market crosses a DST boundaryThe recurrence uses an RRULE with an explicit timezone; the trailing-weeks shift is done in the site's wall clock, so "10am Saturday" stays aligned.
Two operators edit the same zone at onceOptimistic lock: the second save carries the version it started from, no longer matches, and is refused with a conflict. Reload and reapply.

System, data and billing

SituationWhat the system does
The edge box loses internet for daysRollups buffer in SQLite. Sync is a watermark: rows are marked shipped only on a 2xx, and the cloud upserts, so a resend after the link returns is harmless. Data is never lost to a WAN outage within retention.
A sync payload is delivered twiceUpsert on (zone_version_id, bucket_start). Idempotent.
The edge disk fillsOldest shipped rows are rotated out; unsynced data is never dropped. A disk_low alert fires at 20% free.
Power loss mid-writeSQLite WAL, plus an integrity check on boot. A corrupt file is moved aside and recreated; only buffered-but-unsynced buckets in it are lost, same as a long outage.
The edge box is replacedRe-pair from Settings with a new token. The historical cloud data is untouched.
Edge and cloud schema versions differThe cloud rejects a newer payload version (the box keeps buffering until the cloud is updated); older versions are accepted and upgraded.
Clock skew between edge and cloudBucket timestamps are authored on the edge in UTC and the cloud stores them verbatim; it never re-stamps.
A camera is added mid-billing-periodThe prorated change is shown for confirmation before anything is charged. Removing a camera prorates down at the next period, with no mid-period refund by default.
A payment failsA grace window, then the console goes read-only. The edge box keeps collecting the entire time, because the data gap would be unrecoverable, so billing never stops collection. On cancel, an export window, then deletion after the stated period.

8 Supported systems

CamerasONVIF for discovery (WS-Discovery probe) and optional RTSP-URI lookup; any RTSP/H.264 stream otherwise. The onboarding gate enforces a minimum resolution, a minimum decode FPS, and a passing timed test inference before a camera is accepted. TCP transport is forced for reliability over real networks.
Edge hardwareAn x86-64 mini-PC on the property. CPU-only works for a small camera count; the reference box has an NVIDIA RTX 3060 (EDGE_INFERENCE_DEVICE=cuda) and batches inference across streams. Model weights (RT-DETR) download once to a local cache.
Operating systemLinux with systemd for the edge box (edge/deploy/ has the units). The cloud runs anywhere Python 3.12 and Postgres 16 do.
NetworkPrivate mesh (Tailscale). All traffic between the edge box, the cloud API, and the console is machine-to-machine over that mesh, with no public ingress and no CORS surface. Only the venue owner and, for remote support, you.
CloudPostgres 16, Python 3.12, FastAPI. One instance per deployment. Redis is used for background work; WeasyPrint plus Pango for PDF.
BrowserCurrent evergreen desktop browsers. The console is a daytime back-office tool and ships light theme only, by design.
IntegrationsStripe for per-camera subscription billing (webhook signature-verified, quantity always recomputed server-side). Sentry for exceptions, optional and inert unless SENTRY_DSN is set.
What is stored15-minute numeric rollups, zone polygons, tenancies, occupant names, heartbeat health. Never a frame, crop, bounding box, embedding, or movement path. The privacy claim depends on it, and the edge code enforces it.
